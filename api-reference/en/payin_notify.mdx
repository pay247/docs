### Notify URL

The gateway sends `POST` JSON to the `notify_url` supplied at creation. Verify `sign`, identify the order by `mch_order_no`, handle duplicate notifications for the same status idempotently, and process subsequent status changes for that order. Return plain text `SUCCESS` (case and surrounding whitespace are ignored). Other responses trigger retries. Use the query API to reconcile final status. The callback does not include `pay_theme`.

| Field | Present | Type | Description |
|---|---|---|---|
| `mch_id` | Always | string | Merchant ID that owns the order |
| `mch_order_no` | Always | string | Order number supplied by the merchant |
| `order_no` | Always | string | Platform order number generated by Pay247 |
| `status` | Always | string | Order status; handle the actual value, including SUCCESS, FAIL, CLOSED, UNDERPAID, OVERPAID, REFUND (refunded) |
| `currency` | Always | string | Order currency |
| `pay_method` | Always | string | Selected payment method code |
| `amount` | Always | string | Order amount in the order currency |
| `fee` | Always | string | Order fee in the order currency |
| `error` | Always | string | Error; may be empty |
| `created_at` | Always | integer | Created time, milliseconds |
| `payer_name` | Conditional | string | Only returned when the payer's name exists. |
| `paid_at` | Conditional | integer | Only when a paid time exists |
| `actual_amount` | Conditional | string | For allowed under/overpayment or paid v3.0 orders |
| `utr` | Conditional | string | Only for non-FAIL INR orders; may be empty |
| `sign` | Always | string | Callback signature |

```json
{
  "mch_id": "MCH12345678",
  "mch_order_no": "PAYIN-1001",
  "order_no": "PI202609280001",
  "status": "SUCCESS",
  "currency": "INR",
  "pay_method": "UPI",
  "amount": "99.11",
  "fee": "1.00",
  "error": "",
  "created_at": 1693233334134,
  "paid_at": 1693233344134,
  "payer_name": "Jon",
  "actual_amount": "99.11",
  "utr": "123456789012",
  "sign": "<computed signature>"
}
```

### Refund status

A notification with `status` equal to `REFUND` means the system has completed refund processing for the order. It does not mean a refund request is pending. Refund status uses the existing `status` field; no separate refund status field is added. Signature verification and acknowledgment follow the same rules as other payin notifications.

Process a subsequent `REFUND` notification even if a `SUCCESS` notification for the same order has already been handled, and update the order to refunded. Repeated delivery of the same refund notification must not repeat refund business operations. If the status is unclear, reconcile it using [Query payin](/api-reference/en/payin_query).

`amount` and `fee` still represent the original order amount and order fee; neither represents the actual refund amount. `actual_amount` is conditional and is not guaranteed in refund notifications.

#### For example: refunded payin notification

```json
{
  "mch_id": "MCH12345678",
  "mch_order_no": "PAYIN-1001",
  "order_no": "PI202609280001",
  "status": "REFUND",
  "currency": "INR",
  "pay_method": "UPI",
  "amount": "99.11",
  "fee": "1.00",
  "error": "",
  "created_at": 1693233334134,
  "paid_at": 1693233344134,
  "utr": "123456789012",
  "sign": "<computed signature>"
}
```

### Callback response

Return a `Content-Type: text/plain` response body:

| Response body | Result |
|---|---|
| `SUCCESS` | Acknowledged; retries stop. Case and surrounding whitespace are ignored. |
| `FAIL` or anything else | Unacknowledged; the gateway retries with increasing delay. The current payin job normally retries after 10, 100, and 1000 seconds, up to four total attempts. Reconcile final status with the query API. |
